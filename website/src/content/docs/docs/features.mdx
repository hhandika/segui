This page shows what each SEGUL feature does with your data. Each diagram uses a small example; the same rules apply to datasets with thousands of loci. Under each feature, the guide links open its step-by-step instructions for the GUI, CLI, and Python API, or say when an interface does not support it yet. The [Rust](/docs/api-usage/rust-api/) and [R](/docs/api-usage/r-api/) APIs use the SEGUL library directly.

## Task Group

SEGUL groups its features by the kind of input they take. In the GUI, each group is a button in the navigation bar or rail. In the CLI, each group is a command.

<TaskGroups />

The CLI splits the genomic group into three commands: `read` for FASTQ files, `contig` for FASTA contigs, and `maf` for Multiple Alignment Format (MAF) files. The GUI keeps all three in one group.

### Alignments and standard sequence files

Alignment tasks need **alignments**: every sequence in a file has the same length. Partition conversion is the exception and takes partition files, such as RAxML or NEXUS partitions. SEGUL checks only lengths, so it cannot detect misaligned sequences that happen to share a length.

Sequence tasks take aligned or unaligned files and do not check lengths. The documentation calls these **standard sequence files**.

<AlignedVsUnaligned />

## File Input

SEGUL accepts many input files at once. Alignment Splitting is the exception: it takes one concatenated alignment.

### Supported file extensions

<FileFormats />

:::note
SEGUL supports relaxed PHYLIP, not strict PHYLIP. Strict PHYLIP limits sample names to 10 characters and splits sequences into blocks with spaces:

```plaintext
3 20
Seq1      ATCGATCGAT ATCGATCGAT
Seq2      ATCGATCGAT ATCGATCGAT
Seq3      ATCGATCGAT ATCGATCGAT
```

Relaxed PHYLIP allows longer names and writes each sequence without spaces:

```plaintext
3 20
genus_species_museumNo1    ATCGATCGATATCGATCGAT
genus_species_museumNo2    ATCGATCGATATCGATCGAT
genus_species_museumNo3    ATCGATCGATATCGATCGAT
```

:::

## Alignment Task Groups

### Alignment Concatenation

Joins many alignments into one and writes a partition that records where each locus starts and ends. Sequences are matched by sample name, so a typo or inconsistent name leaves a sequence unmatched.

<Guides feature="align-concat" />

<Concatenation />

:::tip
Use [Sequence ID Extraction](#sequence-id-extraction) to check names for typos before concatenating.
:::

### Alignment Conversion

Changes the file format of alignments.

<Guides feature="align-convert" />

<Conversion />

### Alignment Distance

Computes pairwise genetic distances between samples in each alignment. Optionally averages the distances within and between populations or species, using groups from sample names, a regular expression, or a group file, and writes all distances as long tables.

<Guides feature="align-distance" />

<Distance />

### Alignment Filtering

Keeps the alignments that meet a criterion and drops the rest.

<Guides feature="align-filter" />

<Filtering />

### Alignment Partition Conversion

Converts partitions between RAxML and NEXUS formats.

<Guides feature="align-partition" />

<PartitionConversion />

### Alignment Splitting

Splits a concatenated alignment back into separate loci using its partition.

<Guides feature="align-split" />

<Splitting />

### Alignment Summary

Computes summary statistics for a set of alignments at three levels: the whole dataset, each alignment, and each sample.

<Guides feature="align-summary" />

Removes sites, not whole alignments, that have too much missing data or that fall below a count of parsimony-informative characters.

Removes the gaps from every aligned sequence, so you can align the sequences again with a different aligner or settings.

## Genomic Task Groups

### Sequence Read and Contig Summary

Both tasks compute summary statistics for genomic files: raw reads in FASTQ format and assembled contigs in FASTA format.

<Guides feature="genomic-summary" />

<GenomicSummary />

### MAF Conversion

Whole-genome aligners, such as Progressive Cactus and LASTZ with MULTIZ, write Multiple Alignment Format (MAF) files: blocks that align a stretch of a reference genome to other genomes. MAF conversion turns the blocks into alignments that phylogenetic software can read. With a BED file of loci, each block is clipped to every locus it overlaps, and blocks of the same locus are joined across files. Without a BED file, each block, or each reference chromosome, becomes its own alignment.

<Guides feature="maf-convert" />

<MafConversion />

### MAF Summary

Reports the number of blocks, the alignment length, and how much of the reference genome each species covers, so you can check a whole-genome alignment before converting it.

<Guides feature="maf-summary" />

<MafSummary />

Lists every unique sample name across your files.

<Guides feature="sequence-id" />

<SequenceIds />

<Guides feature="sequence-map" />

### Sequence ID Renaming

Replaces sample names across all files using a table of original and new names.

<Guides feature="sequence-rename" />

<Renaming />

### Sequence Addition

Adds sequences to existing files that share the same file name, such as new samples to a set of loci, or collects every sequence into one file. The output is unaligned, ready to realign.

<Guides feature="sequence-add" />

<SequenceAddition />

### Sequence Filtering

Drops single sequences that fail a criterion, such as too few non-gap sites or too many gaps, and keeps the rest of each file. To drop whole alignments instead, use [Alignment Filtering](#alignment-filtering).

### Sequence Removal

Deletes the sequences you select by ID or by a regular expression. Removing a few sequences is faster than extracting the rest.

<Translation />

### Sequence Transposition

Turns locus alignments into one file per sample. Each file holds one sequence for every locus where the sample is present, named after that locus, with gaps and missing data removed.
